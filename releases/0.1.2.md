# 0.1.2 — сбор пула без ошибки, быстрый поиск снова находит, резерв через Tor-мосты

## Что нового

- **Исправлена ошибка «Ошибка сбора пула: Attempt to invoke interface method
  `boolean java.util.List.isEmpty()` on a null object reference».** Причина — в списке мостов
  Tor: пока мосты ни разу не замерялись кнопкой «Проверить мосты», функция упорядочивания
  возвращала `null`, а вызывающий код сразу спрашивал у него `isEmpty()`. Любая попытка
  поднять Tor до первой проверки мостов валила весь сбор пула. Теперь порядок мостов
  подставляется корректно, а источники, DPI-стратегии, пинг и замер изолированы друг от
  друга: сбой одного этапа больше не обрывает сбор.
- **Сбор пула стал заметно быстрее.** Замер данных — **1500 мс** вместо 4000, пинг — **1000 мс**
  вместо 2500, ожидание SOCKS — 3 секунды вместо 4. Сбор идёт в порядке «новые конфиги →
  уже лежащие в пуле», останавливается, как только набралось 25 рабочих, а свежие замеры
  из пула (моложе 12 часов) не перемеряет заново. Старые значения переносятся миграцией,
  так что настройки не нужно править руками.
- **Быстрый поиск снова выдаёт результат.** Две причины и обе устранены: (1) замер пробовал
  ровно первые два URL, а это списки с GitHub — конфиги, которые пускают только Cloudflare и
  CacheFly, отбраковывались как мёртвые; теперь в план замера всегда попадает «дружелюбный»
  источник с CDN. (2) Когда новых конфигов не осталось, поиск честно проверяет до пяти
  лучших из пула — раньше он в этом случае просто заканчивался словами «рабочих нет».
- **Резерв, если VPN не отвечает: трафик через Tor-мосты.** Если «Подключить» не смог поднять
  ни один конфиг (или канал умер, а других рабочих конфигов нет), приложение поднимает Tor с
  мостами, **сначала замеряет скорость** через него — как в «Проверить мосты и источники
  через Tor» — и включает резерв только если порог пройден. Пользователь видит это сразу:
  кнопка становится **фиолетовой**, в статусе — «Tor-мосты · … КБ/с», в консоли — причина
  перехода. DNS не течёт мимо Tor: hev-socks5-tunnel перехватывает запросы (mapdns) и отдаёт
  «fake IP», а имена резолвит сам Tor. Резерв отключается галочкой в настройках.
- **Кнопка «Остановить» работает и во время подъёма Tor.** Tor с мостами может подниматься до
  полутора минут; теперь процесс прерывается сразу, а не после ожидания.

## Сборка

APK собирается автоматически из тега: `aapt2` → `javac` → `d8` → `zipalign` → `apksigner`,
подпись — `debug.keystore` из репозитория. В релизе: `WhitelistBypass-0.1.2.apk`,
`apk.sha256`, `build-report.txt` (badging, содержимое, сертификат, размер).

## Установка

1. Скачайте `WhitelistBypass-0.1.2.apk` из этого релиза.
2. Разрешите установку из неизвестных источников и установите — обновление ставится поверх
   предыдущей версии, данные и пул сохраняются. Таймауты замера и пинга переедут на новые
   значения по умолчанию сами; если вы задавали свои — они останутся.
3. Нажмите «Собрать пул»: теперь он не падает на первом же Tor и заканчивается заметно
   быстрее. Если «Быстрый поиск» раньше заканчивался без результата, попробуйте его снова.
