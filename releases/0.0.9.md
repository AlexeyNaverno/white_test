# 0.0.9 — Tor-канал: переадресации, отказы и запрет обходных путей

## Что нового

- **Переадресации внутри Tor.** Раньше ответ с кодом 302 обрывался ошибкой
  «statusCode can't be in the 300,399 range»: этот диапазон запрещён в ответе, который
  получает WebView. Теперь цепочка переадресаций проходится внутри Tor — до пяти подряд,
  с разворотом относительных адресов и проверкой схемы, — и браузер получает уже конечную
  страницу. Поиск, который раньше падал на первом же редиректе, работает.
- **Проверка «сначала мосты, потом ничего».** `UseBridges 1` теперь безусловно, а при пустом
  списке мостов Tor не поднимается и причину пишет прямо в интерфейс: «нет мостов:
  добавьте их в настройках Tor», «мост не поднялся за N с», «Tor не поднялся с мостами за
  N с». Никакого тихого перехода на открытый канал.
- **Никаких запросов мимо Tor.** Запрос, который нельзя повторить внутри Tor (POST, PUT),
  не отправляется напрямую: вместо этого показывается объяснение. Если поднят туннель,
  приложение предлагает его остановить — иначе трафик пошёл бы через VPN, а не через Tor.
- **Понятные страницы вместо пустого экрана.** Когда Tor не готов, мостов нет или запрос
  заблокирован, открывается короткая страница с причиной — на тёмном фоне, без внешних
  ресурсов.

## Сборка

APK собирается автоматически из тега: `aapt2` → `javac` → `d8` → `zipalign` → `apksigner`,
подпись — `debug.keystore` из репозитория. В релизе: `WhitelistBypass-0.0.9.apk`,
`apk.sha256`, `build-report.txt` (badging, содержимое, сертификат, размер).

## Установка

1. Скачайте `WhitelistBypass-0.0.9.apk` из этого релиза.
2. Разрешите установку из неизвестных источников и установите — обновление ставится поверх
   предыдущей версии, данные и пул сохраняются.
3. Для резервного канала: Настройки → Tor → «Проверить мосты и источники через Tor».
