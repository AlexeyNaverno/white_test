# 0.1.15 — «связность без скорости» в ЧС, списки по сетям, регион и Tor-мост

Пять пунктов по замечаниям: нерабочий VPN, который только отвечает на проверку, больше
не считается рабочим; чёрный список разделён на Wi-Fi и мобильный; нижняя линейка главного
экрана стала квадратной и ничего не переносит; под кнопками появился выбор региона с одной
ссылкой на пинг и одной на загрузку; в настройках — вкладка «Экспериментальное» с Tor-мостом
как VPN и явным разделением «DPI для YouTube/Discord» и «DPI для VPN (VLESS)».

## «Связность есть, скорость не измерена» = нерабочий VPN

Ответ `204` без тела доказывает только то, что сервер отвечает. Скорости в нём нет, а без
скорости конфиг бесполезен: подключиться можно, качать — нечего. Раньше такой результат
засчитывался успехом с фиктивной минимальной скоростью, и конфиг попадал в «Рабочие»,
где занимал место и время перепроверок.

Теперь это провал, причём «жёсткий»:

- в сборе пула и быстром поиске конфиг не попадает в пул;
- он уходит в чёрный список своей сети на неделю;
- при подключении такой конфиг тоже не выбирается: поднимать туннель, который не отдаёт
  данные, бессмысленно.

Порог скорости остался отдельным правилом: медленный конфиг рабочий, просто медленный, и в
чёрный список не попадает.

## Чёрный список разделён: Wi-Fi и мобильный

Пул давно ведётся отдельно по типу сети, а приговор конфигам был общий. Это неверно:
у оператора и домашнего Wi-Fi разные блокировки, и конфиг, не поднявшийся в мобильной сети,
дома часто работает.

- `bypass_blacklist / entries_wifi` — нерабочие в Wi-Fi;
- `bypass_blacklist / entries_lte` — нерабочие в мобильном интернете;
- старый общий список при первом запуске переносится в мобильный (прежние проверки шли в
  основном через мобильный интернет);
- в настройках видно, сколько записей в каждом списке, кнопка очищает оба;
- экран «Рабочие» показывает, к какой сети относится его кнопка «В чёрный список».

## Дизайн главного экрана: квадратные кнопки, ничего не слетает

Причина была в подписях: обычная кнопка с текстом на узком экране переносила «Рабочие» на
вторую строку, и последняя буква уезжала вниз.

- нижняя линейка — пять **квадратов 56 dp** с подписью в одну строку по центру;
- текст не переносится и не обрезается: `singleLine` + `ellipsize`, 11 sp;
- ряд занимает ту же ширину, что и раньше, но выглядит ровно;
- «■ Поиск» во время работы по-прежнему красный и останавливает поиск.

## Целевой регион: Европа, Азия, Америка

Под кнопками появился выбор региона. Регион задаёт **два** адреса, а не набор:

- цель TCP-пинга («интернет вообще есть»);
- ссылка, по которой меряется скорость.

| Регион | Пинг | Скорость |
|---|---|---|
| Европа | `raw.githubusercontent.com:443` | список конфигов с GitHub |
| Америка | `raw.githubusercontent.com:443` | другой файл с GitHub |
| Азия | `www.lenovo.co.jp:443` | главная Lenovo (Япония) |

Почему так: GitHub отдаётся краем Fastly, у которого есть и европейские, и американские
узлы, а его файл нельзя «разрешить точечно» под один сервис — значит, он показывает
настоящий канал. В азиатских сетях GitHub медленнее и хуже достижим, поэтому там —
региональный сайт Lenovo: крупный, не в белых списках, отдаётся локальным краем CDN.

Что изменилось в поведении:

- в настройках по умолчанию одна цель пинга и одна ссылка замера вместо пяти и четырёх;
- набор из пяти маскировал проблему: «работает» могло означать «сработал один из пяти»,
  а скорость мерилась по другому хосту, чем пинг;
- смена региона подставляет его сайты; свои адреса можно вписать руками — кнопка
  «Подставить сайты региона заново» вернёт стандартные;
- старые дефолтные наборы при обновлении заменяются сайтами региона (правленые вручную не
  трогаются).

## Вкладка «Экспериментальное»

Новый раздел в настройках — для способов, которые ведут себя иначе, чем обычный конфиг.

**Tor-мост → подключение вместо VPN.** Приложение поднимает tun, внутри — Tor на
Vanilla-мостах (obfs4/meek и подобные), наружу отдаёт SOCKS5 на `127.0.0.1`, DNS уходит в
Tor. VPN-сервер из пула не используется. Это документированный способ Tor (bridges +
pluggable transports), поэтому он работает там, где VPN-серверы недоступны напрямую и даже
через DPI: мост выглядит как обычный HTTPS к постороннему сайту.

Чем платите: через Tor нет UDP (QUIC, голосовые звонки в играх), скорость обычно
0.5–5 Мбит/с, задержка выше, часть сайтов встречает капчу. Скорость перед подключением
проверяется по тому же порогу, что у конфигов; мосты перебираются по лимиту ожидания из
вкладки «Tor»; «Переключить» в уведомлении возвращает на обычный конфиг из пула.

Кнопки «Включить Tor-мост как VPN» и «Остановить» переехали сюда с вкладки «Tor»; там
остались мосты, лимит ожидания и проверка.

**Два разных DPI — и это не одно и то же:**

- **DPI для VPN (VLESS)** — линия от телефона до VPN-сервера. ciadpi поднимается между
  ядром Xray и сервером и фрагментирует ClientHello, чтобы провайдер не порезал handshake
  по SNI. Настраивается на вкладке «Обход»: общая стратегия, отдельная для Wi-Fi,
  автоподбор, найденные при сборе пула стратегии. На YouTube и Discord это не влияет.
- **DPI для YouTube/Discord** — обход без VPN-сервера: локальный ciadpi фрагментирует TLS
  к самим сервисам, трафик идёт с телефона напрямую. Своя стратегия и свой список адресов —
  вкладка «Только DPI».

Общий у них только движок ciadpi; стратегии, пороги и списки адресов — разные, и менять их
надо по отдельности. Во вкладке «Экспериментальное» есть кнопки быстрого перехода в оба
раздела и объяснение, что где настраивается.

## Мелочи

- Скачанный файл списков теперь чистится только от конфигов, нерабочих в **обеих** сетях:
  он один на Wi-Fi и мобильный, и вычёркивать из него то, что умерло лишь у оператора,
  нельзя — дома такой конфиг может работать. Остальное отсекается на сборке пула.
- Справка обновлена: где порог скорости, что означает 204 без тела, зачем списки по сетям,
  почему на регион одна ссылка.
- Наборы настроек и импорт `.json` не менялись; чёрный список в экспорт не входит.
