# 0.1.20 — рабочие перепроверяются, пул без балласта

Пять правил, которые делают пул честным: в «рабочих» лежит только то, что поднимается
и качает файл **сейчас**, а не «когда-то работало».

## 1. Рабочие — в начало очереди и заново

При сборе конфиги из пула ставятся **первыми**, а сам пул очищается. В рабочие они
возвращаются только если снова подтвердили скорость. Не подтвердил — вылетел молча, без
«мёртвого» балласта, который потом висит в списке и не подключается.

Если сбор остановить до первого подтверждения, старый пул возвращается: «Подключить»
не остаётся без рабочих конфигов.

Отменено прежнее «свежие замеры не перемеряем 24 часа» — именно из-за него в пуле жили
конфиги, которые уже перестали работать.

## 2. «Подключить» — одна попытка, в сохранённом варианте

Конфиг сохраняется **как он работает**: напрямую или через конкретную стратегию
DPI-обхода (пятая колонка в пуле). При подключении делается ровно одна попытка — тем же
способом. Никаких «не вышло напрямую — попробуем с обходом» больше нет, ни при
«Подключить», ни при «Переключить».

Не поднялся — конфиг удаляется из пула и уходит в чёрный список на 7 дней. Исключение —
конфиг, выбранный руками в списке: его не наказываем, просто сообщаем причину.

## 3. В рабочие — только реально измеренная скорость

Файл должен **скачаться целиком** (не меньше 8 КБ прочитанных данных), и скорость должна
пройти порог из настроек. Иначе конфиг получает вердикт «скорость не измерена» и уходит в
**«нерешённые»** — не в рабочие и не в чёрный список: его проверят первым в следующий раз.
Раньше такому конфигу подставлялся порог «для галочки», и он попадал в пул без замера.

## 4. Замер по HTML-странице, а не по файлу с GitHub

Скорость теперь меряется скачиванием HTML-страницы поисковика: **DuckDuckGo без
скриптов** (`html.duckduckgo.com`), в запасе — главная Google. Популярный сайт без
проверки на ботов, тело есть всегда.

Раньше мерили файлом списка с GitHub. Файл сам по себе бывал недоступен — и живой конфиг
выглядел мёртвым, а «медленный» на деле означал «у GitHub проблемы». Скачался HTML
популярного сайта — значит канал открывает интернет целиком, а не только разрешённые
домены.

## 5. Корпус до 50 000 конфигов

Хранилище теперь забивается **до 50 000 строк со всех 12 источников** (было 1200 из 8).
Отсев по чёрному списку и дубликатам делается уже на сборке пула, в памяти — физическая
чистка `configs.txt` отменена, иначе корпус не набрать.

Чтобы это не стоило времени: мёртвые провайдеры (вердикт прошлых прогонов) вычёркиваются
**до** TCP-отсева, а сам отсев идёт по уникальным серверам, а не по строкам.

## 6. Источники качаются только когда обновились

У каждого источника хранится `ETag`/`Last-Modified`. При следующем сборе сервер сам
говорит, изменился ли файл: если нет (HTTP 304) — берётся локальная копия, трафик не
тратится, строки не теряются. Если источник вообще не ответил, тоже берётся копия —
сбор не рвётся и корпус не пустеет.

## Что осталось как было

Партии по 100 в одном ядре, кластеры провайдеров, «нерешённые», чёрный список по сетям,
порог скорости, раздельное туннелирование российского, Tor-резерв, две кнопки на главном
и живой счётчик найденного.
