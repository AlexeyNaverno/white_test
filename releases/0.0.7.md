# 0.0.7 — два секунды на источник, проверка мостов Tor, честный запуск ядра

## Что нового

- **Лимит времени — на каждый источник, а не на всё сразу.** В этих списках килобайты, а не
  мегабайты, поэтому источник получает 2 секунды и не отнимает время у следующих; общего
  лимита на загрузку больше нет. Загрузка через Tor — резервный путь, у неё свой, заметно
  больший лимит (40 секунд на файл), иначе резерв не успевал сработать никогда.
- **Проверка мостов Tor.** В настройках появилась кнопка «Проверить мосты и источники через
  Tor»: Tor поднимается по очереди с каждым мостом, скачивается тестовая страница,
  замеряется скорость, порядок мостов запоминается — дальше используются начиная с самого
  быстрого. Там же видно, реально ли через Tor достаются списки конфигов.
- **«xray startLoop failed» больше не появляется у живых конфигов.** TCP-пинг проходит у
  любого открытого порта, а ядро падало уже внутри, и причину приходилось угадывать. Теперь
  конфиг проверяется до запуска ядра: транспорт (kcp/quic/domainsocket не поддерживаются),
  шифрование (xtls убран из Xray), `flow` (годится только `xtls-rprx-vision` и только на tcp
  с TLS/Reality), `pbk` и `sni` у Reality, формат `id` (UUID), метод Shadowsocks. Такой
  конфиг больше не считается мёртвым — в логе написана причина, а попытка ядра не тратится.
- Добавлена поддержка транспорта `h2`/`http` и проверка результата запуска ядра, а не только
  исключений: если ядро вернуло «не запустилось», это видно сразу.

## Сборка

APK собирается автоматически из тега: `aapt2` → `javac` → `d8` → `zipalign` → `apksigner`,
подпись — `debug.keystore` из репозитория. В релизе: `WhitelistBypass-0.0.7.apk`,
`apk.sha256`, `build-report.txt` (badging, содержимое, сертификат, размер).

## Установка

1. Скачайте `WhitelistBypass-0.0.7.apk` из этого релиза.
2. Разрешите установку из неизвестных источников и установите — обновление ставится поверх
   предыдущей версии, данные и пул сохраняются.
3. Настройки → Tor → «Проверить мосты и источники через Tor», если нужен резервный путь.
