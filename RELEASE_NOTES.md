## Обход Белых Списков 0.0.1

Первая версия после переработки: приложение сведено к трём действиям, а главным
критерием выбора конфига стала **скорость, а не пинг**.

### Главное

- **Подключить** — берёт самый быстрый конфиг из пула, проверяет его (SOCKS + замер
  скорости) и поднимает TUN. Если пул пуст, сам находит рабочий конфиг и подключается.
- **Быстрый поиск** — находит и запоминает один рабочий VPN (пул → пинг → реальная
  проверка, до первого успеха).
- **Собрать пул** — главная функция: скачивает **все** списки со **всех** источников,
  дедуплицирует, пингует и замеряет скорость у живых; в пул попадают только конфиги
  быстрее порога (по умолчанию **128 КБ/с**).

### Как теперь идёт подключение

1. кандидаты берутся из пула — до 6, по убыванию скорости;
2. поднимается Xray на 127.0.0.1:10811, ожидание SOCKS до 6 с;
3. замер скорости: ниже порога — следующий кандидат;
4. если напрямую не вышло — те же конфиги через локальный ciadpi (DPI-обход линии),
   максимум для первых трёх;
5. **TUN создаётся только после успешной проверки** — неудачная попытка больше не
   оставляет телефон без связи;
6. монитор раз в 15 с: при пропадании канала конфиг меняется на следующий по скорости,
   TUN при этом не пересоздаётся.

### Скорость вместо пинга

- порог 128 КБ/с (настраивается), допуск при подключении — 80 % от порога;
- замер = скачать до 512 КБ с иностранного CDN через туннель (минимум 64 КБ выборки);
- сортировка пула — по КБ/с, при равенстве — меньший пинг;
- пинг остался только быстрым фильтром мёртвых перед замером.

### Tor

Только как канал доставки списков: если прямые источники и jsDelivr не отдали ничего,
поднимается TorService, списки качаются через SOCKS 9050, Tor гасится.
Как режим обхода Tor больше не используется.

### Что убрано (3 756 строк вместо 6 133)

- режимы Tor и «Авто» (VPN → Tor → DPI), автогонка топ-3, DPI-обход по умолчанию;
- «Вершина», метки «грузит», списки мёртвых с `.bak`, кэш латентности;
- фоновые докачки через туннель, партии «не более N новых», массовый тест мостов;
- авто-обновление и валидация DPI-стратегий, зеркала GitLab/Codeberg/Bitbucket;
- удаление конфигов по результату теста — теперь ничего не удаляется;
- экран «Список конфигов», TestFlags и TAINT-сборки, настройки-пустышки.

### Важно при обновлении

- формат данных изменился: используются `configs.txt` и `pool.txt`, старые файлы
  игнорируются. После установки нажмите **«Собрать пул»**;
- APK подписан тем же debug-ключом, что и 0.017
  (SHA-256 `de18cb65d3aadc1f7b53372fe896565df2b40f51b9238e4ccef898206dc8d515`),
  поэтому ставится поверх без удаления;
- встроенный резерв сокращён до ~800 строк (было ~2 300) и служит только для первого
  запуска.

### Установка

1. Установите `WhitelistBypass-0.0.1.apk` (разрешите установку из неизвестных источников).
2. Первый запуск → **«Собрать пул»** (5–30 минут в зависимости от сети).
3. Дальше — **«Подключить»**.

Требования: Android 7.0+ (minSdk 24), ARM (`armeabi-v7a`, `arm64-v8a`).

### Сборка из исходников

    tools/fetch_deps.sh deps
    ./build.sh /opt/android-sdk ./deps
    sha256sum WhitelistBypass.apk

Нужны JDK 17 или 21, Android SDK (platform 36, build-tools 36.0.0) и ~75 МБ
зависимостей (libv2ray, tor-android, jtorctl, kotlin-stdlib, localbroadcastmanager).
Готовый конвейер — `.github/workflows/build-apk.yml`: пуш тега `v*` собирает APK
и прикладывает его к релизу.

### Ограничения

1. Публичные конфиги живут недолго — пул нужно периодически пересобирать.
2. DPI-обход линии — вспомогательный путь: фрагментация TLS ломает Reality, поэтому он
   применяется только после неудачной прямой попытки.
3. Tor без obfs4/webtunnel (плагинов в APK нет) работает только на Vanilla-мостах.
4. IPv6 по умолчанию не маршрутизируется (включается в настройках).
5. Подключение идёт к сторонним серверам из публичных подписок — на свой риск.
6. APK собран без запуска на устройстве: проверены сборка, подпись и метаданные,
   но не поведение туннеля.
