# Обход Белых Списков

Android-приложение для подключения к интернету через публичные VPN-конфигурации
(VLESS / Trojan / Shadowsocks / VMess) на встроенном ядре Xray. Списки конфигов
загружаются из открытых репозиториев, проверяются реальной загрузкой и складываются
в пул рабочих — подключение всегда идёт с самого быстрого.

**Последний релиз:** [github.com/AlexeyNaverno/white_test/releases/latest](https://github.com/AlexeyNaverno/white_test/releases/latest)

## Что это

Базово это Android-приложение с **одной кнопкой «Подключить»**: всегда VPN
(VLESS / Trojan / Shadowsocks / VMess через встроенный Xray-core), при необходимости —
с DPI-обходом линии. Главный критерий выбора конфига — **скорость, а не пинг**: пул
сортируется по КБ/с, конфиги медленнее порога (по умолчанию **128 кбит/с = 16 КБ/с**)
в пул не попадают вообще.

Tor встроен ровно для одного: скачать списки конфигов, когда прямые источники и зеркало
недоступны. Как режим обхода он не используется.

Своих серверов у приложения нет: оно не продаёт подписки, не собирает статистику и не
отправляет ничего «своему» сервису. Всё, что делает телефон в сети, — это запросы к
публичным спискам конфигов и к тем серверам, которые в этих списках указаны.

## Три действия

| Кнопка | Что делает |
|---|---|
| **Подключить** | Берёт самый быстрый конфиг из пула, проверяет его (SOCKS + замер скорости) и поднимает туннель. Пул пуст — сам находит рабочий конфиг и подключается. |
| **Быстрый поиск: найти 1 рабочий VPN** | Проверяет сеть, затем лучшие из пула, затем списки: пинг партиями → проверка живых до первого рабочего. Когда кандидаты кончились — догружает источники по одному файлу, в конце (один раз) пробует Tor. |
| **Собрать пул** | Обновляет **все** списки со **всех** источников, дедуплицирует, пингует и замеряет скорость у живых; в пул попадают только прошедшие порог — с замером КБ/с. |

Подключение всегда двухступенчатое: сначала ядро поднимает локальный SOCKS и скорость
проверяется реальной загрузкой, и только потом создаётся TUN. Неудачная попытка не
оставляет телефон без связи. После подключения работает монитор: если канал пропал,
конфиг меняется на следующий по скорости.

## Требования и установка

- Android 7.0+ (minSdk 24), ARM — `armeabi-v7a` и `arm64-v8a`.
- Разрешение на VPN (стандартный запрос Android при первом подключении).

1. Скачайте `WhitelistBypass-<версия>.apk` из [последнего релиза](https://github.com/AlexeyNaverno/white_test/releases/latest).
2. Разрешите установку из неизвестных источников и установите APK.
3. Первый запуск → **«Собрать пул»** (5–30 минут, зависит от сети).
4. Дальше — **«Подключить»**.

APK подписан debug-ключом, который лежит в репозитории (`debug.keystore`), поэтому
обновления ставятся поверх без удаления. Для распространения в маркете нужен отдельный
релизный ключ.

## Источники конфигов по умолчанию

Приложение ничего не «знает» само: списки берутся из открытых репозиториев. По умолчанию
используются:

| Репозиторий | Файлы |
|---|---|
| [luxxuria/harvester](https://github.com/luxxuria/harvester) | `speed_tested.txt` (топ по скорости), `ping_tested.txt` |
| [kort0881/vpn-vless-configs-russia](https://github.com/kort0881/vpn-vless-configs-russia) | `data/githubmirror/ru-sni-local/vless.txt`, `data/githubmirror/clean/vless.txt` |
| [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia) | `BLACK_VLESS_RUS_mobile.txt`, `Vless-Reality-White-Lists-Rus-Mobile.txt`, `WHITE-CIDR-RU-all.txt`, `BLACK_VLESS_RUS.txt` |
| [wlunlocker/vpn-configs](https://github.com/wlunlocker/vpn-configs) | `whitelist_all.txt` |
| [ByeWhiteLists/ByeWhiteLists2](https://github.com/ByeWhiteLists/ByeWhiteLists2) | `ByeWhiteLists2.txt` |
| [tiagorrg/vless-checker](https://github.com/tiagorrg/vless-checker) | `docs/keys.json` (результаты автопроверки ключей по странам) |
| [26info/vless-proxy-list](https://github.com/26info/vless-proxy-list) | `working-proxies.txt` |

Порядок не случайный: сначала идут небольшие списки, которые их авторы уже проверили на
пинг и скорость, потом массовые сборники, а самый большой файл — последним (до него дело
обычно не доходит: число хранимых конфигов ограничено). Из JSON-списков ссылки
вытаскиваются как есть, поэтому файл не обязан быть «одна строка — один конфиг».

Если основной адрес недоступен, тот же файл запрашивается через зеркало jsDelivr; если
недоступны все — списки скачиваются через Tor. Список источников редактируется в
настройках (по одному URL на строку), туда можно добавить свои.

Лимит считается **на каждый источник отдельно — 2 секунды**: в этих файлах килобайты,
и медленнее тянуть смысла нет. Общего «на всё про всё» лимита нет, поэтому один
медленный репозиторий не отнимает время у остальных. У загрузки через Tor лимит свой и
заметно больше (40 секунд на файл): это резервный путь, и он по определению медленный.

## Стратегии DPI-обхода

DPI-обход линии строится на аргументах [ciadpi](https://github.com/hufrea/byedpi)
(ByeDPI): фрагментация TLS, disorder, фейковые пакеты и т.п. Рабочая стратегия зависит от
провайдера и от того, что именно блокируют, — одна «на все случаи» живёт недолго. Поэтому
список стратегий обновляется из открытых репозиториев, где авторы сами гоняют их по
блокировкам:

| Репозиторий | Файл |
|---|---|
| [romanvht/ByeByeDPI](https://github.com/romanvht/ByeByeDPI) | `app/src/main/assets/proxytest_strategies.list` |
| [alimali54/DPIscord](https://github.com/alimali54/DPIscord) | `linux/byedpi/strategies.txt` |

Как это работает:

1. **Автообновление.** Нажатие «Обновить стратегии с GitHub» в настройках (а также каждый
   «Собрать пул») скачивает эти файлы, отбрасывает комментарии и мусор, складывает
   стратегии в `files/strategies.txt`; встроенный минимум остаётся всегда.
2. **Проверка.** Кнопка «Проверить стратегии сейчас» и автоподбор при подключении по
   очереди поднимают ciadpi с очередной стратегией и идут через неё на заблокированные
   адреса (Discord, YouTube, Instagram — список задаётся в настройках). Стратегия считается
   рабочей, если отдал хотя бы один из адресов.
3. **Сохранение.** Первая прошедшая стратегия записывается в настройки и применяется к
   линии до VPN-сервера при следующих подключениях. Автоподбор можно выключить — тогда
   используется ровно та стратегия, что стоит в поле настроек.

Поддерживаются оба формата аргументов: короткий (`-d1 -s3+sm -a1`) и длинный
(`--disorder 1 --auto=torst`); `{sni}` и `{port}` подставляются автоматически. Стратегии
для `zapret`/`nfqws` (формат `PROTO|ARGS`) не подходят и не используются.

## Резервный канал Tor

Tor в приложении нужен для одного: достать списки конфигов, когда прямые источники и
зеркало не отдали ничего. **Мосты включены всегда** — Tor без мостов не поднимается: без
них это просто медленный обычный интернет, для которого есть обычный браузер. Нет мостов —
приложение честно об этом пишет, вместо того чтобы молча ходить открытым каналом.

Резерв проверяется, а не предполагается — в настройках есть кнопка
**«Проверить мосты и источники через Tor»**:

1. Tor поднимается по очереди с каждым мостом (до шести), скачивается тестовая страница,
   замеряется скорость.
2. Порядок запоминается: дальше и в приложении, и в браузере мосты используются начиная
   с самого быстрого.
3. Затем через Tor реально проверяются первые источники списков — видно, что резервный
   путь работает и сколько времени он занимает.

Проверка долгая (до нескольких минут) и запускается вручную.

## Совместимость конфигов с ядром

TCP-пинг проходит у любого живого порта, поэтому перед запуском ядра конфиг проверяется
на совместимость: транспорт (`kcp`, `quic`, `domainsocket` не поддерживаются), шифрование
(`xtls` из Xray убран), `flow` (годится только `xtls-rprx-vision` и только на tcp с
TLS/Reality), наличие `pbk` и `sni` у Reality, формат `id` (UUID), метод Shadowsocks.
Несовместимый конфиг не считается мёртвым — в логе видна причина, а ядро не тратит на
него попытку.

## Встроенный браузер (только через Tor)

В настройках, под кнопкой «Сохранить», есть браузер на одну вкладку: поиск по умолчанию —
DuckDuckGo, всё управление сверху (адрес, «→», меню «⋮» со «Скачать страницу», «Мосты» и
«Выйти»). Он ходит **только через Tor с мостами** — это не переключатель, а правило:

- мостов нет → Tor не поднимается, страницы не открываются, причина написана на экране;
- туннель VPN включён → браузер попросит его остановить, иначе трафик пойдёт через VPN;
- запросы, которые нельзя повторить (POST), не отправляются напрямую — вместо этого
  показывается объяснение;
- переадресации (в том числе поиск DuckDuckGo) проходятся внутри Tor, до пяти подряд.

Страница сохраняется в MHTML — один файл, внутри и разметка, и картинки.

## Проверка сети и замер скорости

Цели TCP-пинга — сервисы **вне белых списков** (`discord.com`, `www.instagram.com`, `x.com`,
`www.facebook.com`, `www.youtube.com`): если провайдер пускает только по белому списку, эти
адреса не ответят, а разрешённые сайты ответят всегда — по ним нельзя понять, работает ли
обход. По той же причине в проверке канала через туннель не используются разрешённые сервисы.

Скорость меряется **на маленьких файлах** (32 и 128 КБ, плюс резервные небольшие файлы) и
в несколько дорожек параллельно (по умолчанию 4): канал видно уже по первым килобайтам,
мегабайты качать незачем. Ожидание SOCKS — 4 секунды, порог «рабочего» конфига по умолчанию
128 кбит/с = 16 КБ/с.

## Быстрый поиск и пул

- **Быстрый поиск** ищет **новые** конфиги и не перепроверяет то, что уже лежит в пуле: его
  задача — добавить ещё вариант для стабильности или скорости.
- **Собрать пул** — единственное место, где проверяются все: пинг, замер скорости, пул
  заменяется целиком, поэтому мёртвое и медленное из него уходит.

## Импорт и экспорт пула

Настройки → «Пул: импорт и экспорт»:

- **Экспорт** — обычный `.txt`, по одной ссылке на строку (по убыванию скорости).
- **Импорт** — дубликаты отбрасываются (и внутри файла, и уже имеющиеся в пуле), остальные
  пингуются, затем у живых замеряется скорость; в пул попадают только прошедшие порог.

## DPI-обход по умолчанию выключен

Стратегии ciadpi — это надстройка на случай, когда прямое подключение не проходит, поэтому
по умолчанию и DPI-обход линии, и автоподбор стратегий **выключены**. Включаются галочками в
настройках: тогда при неудачном прямом подключении приложение подбирает стратегию и
применяет её к линии до VPN-сервера.

## Как устроен репозиторий

```
src/ru/whitelist/bypass/   исходники (Java), точки входа: MainActivity, BypassVpnService,
                           BrowserActivity — встроенный браузер на одну вкладку,
                           Ui — отступы под системные панели (Android 15+ рисует под ними)
res/                       ресурсы интерфейса, иконка, темы
assets/fallback/           небольшой встроенный резерв конфигов (первый запуск)
jniLibs/<abi>/             готовые нативные библиотеки: ByeDPI, hev-socks5-tunnel, Tor
tools/fetch_deps.sh|.bat   скачивание зависимостей сборки (AAR/JAR, ~75 МБ)
build.sh / build.bat       сборка APK без Gradle (aapt2 + javac + d8 + apksigner)
.github/workflows/         CI: сборка APK и артефакты релиза
releases/                  тексты релизов по версиям
AndroidManifest.xml        манифест, версия, компоненты
```

CI собирает APK на каждый тег `v*`: ставит JDK и Android SDK, скачивает зависимости,
проверяет версию, подпись и содержимое APK и прикладывает к релизу сам APK, `apk.sha256`
и `build-report.txt` (badging, список файлов, сертификат, размер).

## Сборка из исходников

Нужны JDK 17+, Android SDK (platform 36, build-tools 36.0.0) и ~75 МБ зависимостей:

```bash
tools/fetch_deps.sh /путь/к/deps          # Windows: tools\fetch_deps.bat deps
./build.sh /путь/к/android-sdk /путь/к/deps
#   → WhitelistBypass.apk
#   ABIS="arm64-v8a" ./build.sh …        (по умолчанию armeabi-v7a + arm64-v8a)
```

Windows: `build.bat` (SDK ожидается в `C:\SDK`, переменные `ABIS`, `DEPS`).
Зависимости: `libv2ray.aar` (AndroidLibXrayLite), `tor-android.aar`, `jtorctl`,
`kotlin-stdlib`, `localbroadcastmanager`. Нативные `libbyedpi.so` уже лежат в `jniLibs/`.
