# Обход Белых Списков 0.0.1

Android-приложение: **одна кнопка «Подключить»**, всегда VPN (VLESS / Trojan / Shadowsocks /
VMess через встроенный Xray-core), при необходимости — с DPI-обходом линии. Главный критерий
выбора конфига — **скорость, а не пинг**: пул сортируется по КБ/с, конфиги медленнее порога
(по умолчанию **128 КБ/с**) в пул не попадают вообще.

Tor встроен ровно для одного: скачать списки конфигов, когда прямые источники и зеркало
недоступны. Как режим обхода он не используется.

---

## Три действия

| Кнопка | Что делает |
|---|---|
| **Подключить** | Берёт самый быстрый конфиг из пула, проверяет его (SOCKS + замер скорости ≥ порога), поднимает TUN. Пул пуст → сам ищет рабочий конфиг и подключается к нему. |
| **Быстрый поиск: найти 1 рабочий VPN** | Проверяет лучший из пула; если он не проходит — пинг всех списков и реальная проверка до 20 кандидатов. Найденный сохраняется в пул и в «текущий». |
| **Собрать пул** | Главная функция: **скачивает все списки со всех источников**, дедуплицирует, пингует, затем до 300 живых проверяет реальным запросом через Xray и записывает в пул только прошедших порог скорости — с замером КБ/с. |

Повторное нажатие на идущий поиск/сбор — остановка (уже найденное сохраняется).

## Как идёт трафик

```
приложение → TUN (10.10.10.10/32, 0.0.0.0/0)
            └─ hev-socks5-tunnel → 127.0.0.1:10811 (SOCKS5)
                                    └─ Xray-core → VLESS/Trojan/SS/VMess → сервер
                                    └─ (опция) локальный ciadpi → DPI-обход линии
```

Порядок запуска — важная деталь, которая отличает 0.0.1 от предыдущих сборок:

1. берём кандидатов из пула (до 6, по убыванию скорости);
2. поднимаем Xray на `127.0.0.1:10811` и ждём SOCKS (до 8 с);
3. меряем скорость; ниже порога — следующий кандидат;
4. если напрямую не вышло и включён DPI-обход — повторяем те же конфиги через локальный
   ciadpi (только первые 3 конфига: TLS к серверу фрагментируется, для Reality это часто
   бесполезно);
5. **только после успеха** создаём TUN и поднимаем hev-socks5-tunnel;
6. монитор раз в 15 с проверяет канал; при отсутствии ответа дольше «секунд до переключения»
   конфиг меняется на следующий по скорости (TUN при этом не пересоздаётся).

Пока идёт поиск, интернет на телефоне остаётся рабочим — TUN ещё не поднят.

## Политика скорости

- Порог задаётся в настройках, по умолчанию **128 КБ/с**.
- Замер = скачать до 512 КБ с иностранного CDN **через туннель** и посчитать КБ/с
  (минимум 64 КБ данных, иначе замер считается недостоверным).
- В пул попадают только конфиги с замером ≥ порога; порядок в пуле — по скорости по убыванию,
  при равной скорости — по меньшему пингу.
- При подключении допуск 80% от порога (сеть «дышит»).
- Пинг (TCP/TLS-handshake) используется только как быстрый фильтр мёртвых перед замером.

## Хранение

| Файл | Что внутри |
|---|---|
| `files/configs.txt` | всё, что скачано со всех источников (до 2 000 строк, дедуп по схеме+host+port+user) |
| `files/pool.txt` | `КБ/с ⇥ пинг ⇥ время замера ⇥ конфиг`, до 200 строк, отсортировано по скорости |
| `assets/fallback/` | встроенный резерв на первый запуск: `vless_black_mobile`, `vless_white_reality_mobile`, `wlunlocker_all` (~800 строк) |
| `files/TorService/torrc` | конфиг Tor: `SocksPort 9050` + мосты (свои из настроек либо встроенные Vanilla) |

Данные предыдущих версий (`downloaded.txt`, латентность, «вершина», списки мёртвых) намеренно
не читаются: формат и логика изменились.

## Настройки

Оставлено только то, что влияет на работу:

- **Скорость** — порог КБ/с, файлы для замера, таймаут замера;
- **Поиск** — потоков пинга, таймаут пинга;
- **Источники** — до 6 URL по умолчанию (igareck, wlunlocker, ByeWhiteLists), правятся списком;
- **DPI-обход** — включатель и одна стратегия ciadpi;
- **Сеть** — DNS туннеля, IPv6, автопереключение и его тайминги, автозапуск при загрузке;
- **Tor** — мосты и доп. строки torrc (только для скачивания списков);
- **Данные** — встроенный резерв, удаление скачанных списков и пула, разрешение на работу в фоне.

## Сборка (без Gradle: aapt2 + javac + d8)

Нужны JDK 17+, Android SDK (platform 36, build-tools 36.0.0) и зависимости (AAR/JAR, ~75 МБ):

```bash
tools/fetch_deps.sh /путь/к/deps          # Windows: tools\fetch_deps.bat deps
./build.sh /путь/к/android-sdk /путь/к/deps
#   → WhitelistBypass.apk
#   ABIS="arm64-v8a" ./build.sh …        (по умолчанию armeabi-v7a + arm64-v8a)
```

Windows: `build.bat` (SDK ожидается в `C:\SDK`, переменные `ABIS`, `DEPS`).

Сборка ставит `minSdk 24`, `targetSdk` из платформы, подписывает debug-ключом
(пересоздаётся автоматически, если файла нет). Для постоянного использования подпишите
релизным ключом:

```bash
zipalign -p -f 4 app-unsigned.apk app-aligned.apk
apksigner sign --ks my-release.jks --out WhitelistBypass.apk app-aligned.apk
```

Зависимости, которые тянет `fetch_deps`: `libv2ray.aar` (AndroidLibXrayLite 26.10.31),
`tor-android.aar` 0.4.9.13.2, `jtorctl`, `kotlin-stdlib`, `localbroadcastmanager`.
Нативные `libbyedpi.so` (ciadpi + hev-socks5-tunnel + JNI) лежат готовыми в `jniLibs/`;
пересборка требует NDK и исходников `../native-src`.

## Что изменилось относительно 0.017

Удалено (около 3 900 строк и 700 КБ ассетов):

- режимы **Tor** и **Авто** (VPN → Tor → DPI) и переключатель режимов;
- **автогонка топ-3** (три инстанса Xray одновременно) и **DPI-обход линии по умолчанию**;
- «**Вершина**» (`tower.txt`), метки «грузит» (`data_ok.txt`), списки мёртвых с `.bak`,
  кэш латентности — вместо них один `pool.txt` по скорости;
- **фоновые докачки** в туннеле и «тихое обновление», обновление мостов Tor с 6 URL,
  массовый TLS-тест мостов, авто-обновление и валидация списков стратегий DPI;
- **удаление конфигов по результату теста** (`deleteByHashes`) — теперь ничего не удаляется;
- партии («не более 100 новых за вызов»), лимиты 300 за обновление, зеркала
  GitLab/Codeberg/Bitbucket (осталось одно рабочее — jsDelivr);
- экран «Список конфигов», `TestFlags` и TAINT-сборки, `tools/taint_manifest.*`,
  настройки-пустышки (`pingTargets`, `byedpiDns`), `LatencyStore`;
- встроенный резерв сокращён с 2 300 до ~800 строк, список из 111 DPI-стратегий удалён
  (осталась одна стратегия, редактируемая в настройках).

Изменено:

- **TUN создаётся после проверки ядра**, а не до неё — неудачная попытка больше не оставляет
  телефон без связи;
- гейт «1 МБ за 2 с» заменён на порог **128 КБ/с** с настраиваемым значением;
- подключение короче: 6 кандидатов, проверка SOCKS до 8 с, DPI-обход — только как второй шанс;
- приоритет в пуле и при подключении — **скорость**, а не пинг.

## Ограничения, о которых честно

1. Публичные конфиги живут недолго: пул стареет, «Собрать пул» нужно повторять.
2. Пинг проверяет только достижимость `IP:port`. Реальную рабочесть даёт только замер через Xray.
3. DPI-обход линии — вспомогательный путь: фрагментация TLS ломает Reality/xtls, поэтому он
   применяется только после неудачной прямой попытки и только для первых трёх конфигов.
4. Tor без obfs4/webtunnel (плагинов в APK нет) работает только на Vanilla-мостах и под ТСПУ
   часто не поднимается вовсе — поэтому он и вынесен в «последнее средство» для скачивания.
5. IPv6 по умолчанию не маршрутизируется (включается в настройках).
6. `x86`/`x86_64` в APK по умолчанию нет: `ABIS="arm64-v8a x86_64" ./build.sh …`.
7. Приложение подключается к сторонним серверам из публичных подписок — используйте на свой
   риск и в соответствии с законодательством вашей страны.
