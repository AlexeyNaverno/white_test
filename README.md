# Обход Белых Списков

Android-приложение для обхода блокировок («белые списки», DPI-ограничения) без
серверов самого приложения. Весь трафик идёт через движки, встроенные в APK:

| Режим | Движок | Как работает |
|-------|--------|--------------|
| **DPI-обход** | [ByeDPI](https://github.com/hufrea/byedpi) (`ciadpi`) | Локальный SOCKS5 на 127.0.0.1:10810, DPI-стратегии (TLS-фрагментация и т.п.), трафик TUN → hev-socks5-tunnel → SOCKS |
| **VPN (конфиги)** | [Xray-core](https://github.com/XTLS/Xray-core) (AndroidLibXrayLite, `libv2ray`) | VLESS (+Reality/Vision), Trojan, Shadowsocks, VMess; локальный SOCKS5 на 127.0.0.1:10811 |
| **Tor** | [tor-android](https://guardianproject.info/apps/tor/) 0.4.9.13.2 | Tor с мостами (Vanilla из резерва или свои), SOCKS5 на 127.0.0.1:9050 |

Все движки работают **внутри процесса приложения**, поэтому приложение исключается
из TUN (`addDisallowedApplication`), а DNS резолвится внутри туннеля.
Пакет: `ru.whitelist.bypass` · **minSdk 24** · targetSdk 36 · ABIS по умолчанию:
`armeabi-v7a`, `arm64-v8a`.

## Установка

```bash
adb install -r WhitelistBypass.apk
```

APK в корне репозитория подписан **debug-ключом** (CN=Android Debug, O=WhitelistBypass) —
только для установки/знакомства. Для постоянного использования подпишите релизным ключом:

```bash
zipalign -p -f 4 app-unsigned.apk app-aligned.apk
apksigner sign --ks my-release.jks --out WhitelistBypass.apk app-aligned.apk
```

> Никогда не коммитьте релизный ключ. `debug.keystore` в `.gitignore`, пересоздаётся сборкой.

## Возможности

- **Три движка** на выбор с главного экрана: DPI / VPN / Tor.
- **Источники конфигов** (по умолчанию 8, все проверены 05.11.2026):
  igareck/vpn-configs-for-russia (BLACK_VLESS_RUS_mobile, Vless-Reality-White-Lists-Rus-Mobile,
  WHITE-CIDR-RU-checked, BLACK_SS+All_RUS, BLACK_VLESS_RUS),
  wlunlocker/vpn-configs (whitelist_all, blacklist_vpn1),
  ByeWhiteLists/ByeWhiteLists2. Список правится в «Настройки → Источники» (по одному URL на строку).
- **Пачками, не всем скопом**: скачивание новой порции (по умолчанию ≤100 конфигов за партию,
  не более 300 за полное обновление), каждая партия сразу пингуется (100 потоков),
  мёртвые отбраковываются и не сохраняются.
- **Встроенный резерв** (`assets/fallback/`, срез от 05.11.2026): используется на первом запуске,
  если интернет/GitHub ещё недоступен, и дополняет загруженные конфиги. Отключается в настройках
  («Встроенные резервные конфиги»), удалить файлы невозможно.
- **Тихое фоновое докачивание**: только при выключенном туннеле, достаточной скорости
  (по умолчанию ≥256 КБ/с) и доступности GitHub; отключается в настройках.
- **Мониторинг канала**: каждые N секунд проверка, при отсутствии ответа дольше
  «Секунд без ответа до автопереключения» — автоматическое переключение на следующий
  живой конфиг (VPN) или следующую встроенную стратегию (DPI). Для Tor автопереключение
  не выполняется (только подсказка проверить мосты).
- **Кэш задержек** host:port → ms (`latency_cache_v1`), лучший конфиг выбирается автоматически.
- **GitHub напрямую в РФ нестабилен**: перед скачиванием `github.com:443` пингуется,
  при провале пробуются резервные IP (порт 443, настраиваются в разделе «GitHub»).
- Редактор всего: источники, адреса пинга, потоки/таймауты, батч, стратегия ByeDPI,
  DNS, мосты Tor, доп. torrc.

## Разрешения для работы в фоне

- **POST_NOTIFICATIONS** (Android 13+) — запрашивается при первом запуске; уведомление — статус и «вкл/выкл» VPN.
- **REQUEST_IGNORE_BATTERY_OPTIMIZATIONS** — чтобы ОС не выгружала приложение из памяти и туннель не рвался в фоне.
  Системный диалог показывается один раз при первом запуске; повторно — в «Настройки → Фоновая работа».

## Если приложение падает при запуске («Приложение остановлено»)

Начиная с этой версии при любом непойманном исключении стектрейс сохраняется в
`filesDir/last_crash.txt`, а при следующем запуске показывается полноэкранный диалог
с текстом ошибки. **Просто снимите скриншот этого диалога и пришлите** — причина будет
очевидна без adb/logcat.

## Ограничения и честные оговорки

1. **Гарантия скорости — большие public-конфиги бесплатны**: сотни доступных конфигов
   из публичных срезов часто перегружены или мертвы — от этого и пингование пачками.
2. TCP-пинг проверяет только достижимость `IP:port`, а не «настоящий» прокси-рукопожатие.
3. Tor: встроенные мосты — **Vanilla** (IP:port, plain ORPort). obfs4/webtunnel требуют
   плагины (lyrebird/webtunnel), которых в APK нет — свои мосты/плагин добавляйте сами.
4. **Автоподключение при загрузке** на Android 12+ часто блокируется системой.
   Надёжный способ — системная настройка «Всегда включённый VPN» для приложения.
5. `x86`/`x86_64` в APK по умолчанию нет — добавьте: `ABIS="armeabi-v7a arm64-v8a x86 x86_64" ./build.sh …`.
6. Пустые/удалённые источники пропускаются; мёртвые URL из свежего среза удалены из
   значений по умолчанию (kort0881 githubmirror → 404 на 05.11.2026).
7. Приложение подключается к сторонним серверам из ваших подписок — используйте на свой
   риск и в соответствии с законодательством вашей страны.

## Сборка из исходников (без Gradle, только aapt2/javac/d8)

### Зависимости (один раз)

```bash
# 1) JDK 17+ (Temurin или системный)
# 2) Android SDK: platform 36 + build-tools 36.0.0 — через sdkmanager:
mkdir -p /путь/к/android-sdk/cmdline-tools
#   скачайте commandlinetools-linux-*_latest.zip с dl.google.com и распакуйте в cmdline-tools/latest
yes | /путь/к/android-sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=/путь/к/android-sdk --licenses
/путь/к/android-sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=/путь/к/android-sdk \
    "platforms;android-36" "build-tools;36.0.0"
# 3) библиотеки приложения (AAR/JAR, ~73 МБ):
tools/fetch_deps.sh /путь/к/deps     # Linux/mac  (Windows: tools\fetch_deps.bat deps)
```

> Замечание: папка `deps/` не хранится в репозитории — всё скачивается скриптами
> выше. APK самодостаточен: для установки и работы ничего из deps не нужно.

Скачиваются в `deps/`: libv2ray 26.10.31 (AndroidLibXrayLite AAR, 60 МБ),
tor-android 0.4.9.13.2 AAR, jtorctl 0.4.5.7, kotlin-stdlib 2.2.10,
localbroadcastmanager 1.1.0, android-sdk (platform 36 + build-tools 36.0.0),
JDK 17+ (в комплекте Temurin 17; можно и системный).

Для пересборки нативных `libbyedpi.so` / `libhev-socks5-tunnel.so` нужен Android NDK
(протестировано с r27c) и исходники в `../native-src` (уже в комплекте).

### Linux / macOS

export JAVA_HOME=/путь/к/jdk   # нужен javac 17+

# → WhitelistBypass.apk в корне

Ожидаемая структура `C:\SDK`:

```
C:\SDK\cmdline-tools\latest\bin\sdkmanager.bat   (или …\cmdline-tools\bin)
C:\SDK\platforms\android-36\android.jar

```

```bat

```

Зависимости в bat по умолчанию берутся из `deps\` в корне проекта (рядом с build.bat).

### Что делает сборка (7 шагов)

1. `aapt2 compile` (res → .flat) → `resources.zip`
2. `aapt2 link` → `base.apk` + `R.java`
3. `javac --release 8` (classpath: android.jar + классы AAR/Jar) → `build/classes`
4. `d8 --min-api 24` (классы приложения + распакованные классы AAR + jars; AAR-классы
   извлечены в jar-файлы) → `classes.dex`
5. `jar uf base.apk classes.dex` + нативные `.so` в `lib/<abi>/`
6. `zipalign -p 4`
7. `apksigner sign` (debug.jks; генерируется автоматически)

## Дисклеймер

Приложение — клиент для публичных бесплатных конфигов и Tor. Оно не предоставляет
доступ к сети само по себе и не гарантирует доступность каких-либо ресурсов.
Использование — на ваш риск; соблюдайте законодательство. Автор кода не связан с
проектами Xray-core, ByeDPI, tor-android, igareck.

## Этапные тестовые сборки (TAINT) — пошаговый поиск причины вылетов без logcat

`build.sh` (Linux/macOS) и `build.bat` (Windows) поддерживают переменную `TAINT`
со значениями 1..4. Полная сборка по умолчанию (4). Этапные сборки подписываются
тем же `debug.keystore`, поэтому ставятся поверх предыдущей версии без удаления.

Зависимости этапов:

| TAINT | Файл | Что внутри | Что проверяет тестер |
|-------|------|-----------|----------------------|
| 1 | `WhitelistBypass-TEST1.apk` | Только интерфейс: НЕТ сервисов, BootReceiver и НИ ОДНОГО native .so | Окно открывается → проблема в системном/упаковочном уровне выше кода приложения; падает → не зависит от сервисов/нативов |
| 2 | `WhitelistBypass-TEST2.apk` | + DPI-обход (byedpi + hev .so, BypassVpnService). Tor и Xray/libgojni НЕ в APK, режим DPI разрешён | Тестируется весь путь DPI: VPN-разрешение, TUN, ByeDPI |
| 3 | `WhitelistBypass-TEST3.apk` | + Xray/libgojni (VPN-обход по конфигам). Tor НЕ включён | Тестируется путь Xray |
| 4 | `WhitelistBypass.apk` | Полная сборка: + Tor (libtor.so, TorService) и автообновление/фоновые задачи | Полная функциональность |

Сборка этапного APK:

```bash
TAINT=2 ./build.sh /path/to/sdk /path/to/deps          # Linux/macOS
```
```bat
set TAINT=2 ^&^& build.bat                              REM Windows (cmd)
```

Что отключается по этапам: TEST1 — все `<service>`/`<receiver>`, разрешения
FOREGROUND_SERVICE*/WAKE_LOCK/BOOT/IGNORE_BATTERY_OPT, нативные библиотеки
(файл ~0.8 МБ); TEST2/TEST3 — без `<service org.torproject.jni.TorService>`;
TEST2 — без `libgojni.so`; TEST2/TEST3 — без `libtor.so`. В TEST1–TEST3 кнопка
питания принимает только свой режим (TEST1 — заблокирована) и показывает тост.
Тестовые сборки имеют versionName `1.0-testN`.

Инструменты: `tools/taint_manifest.py` (Linux) и `tools/taint_manifest.ps1` (Windows,
через встроенный PowerShell — Python на машине не требуется). Оба скрипта идемпотентны
и используются автоматически из `build.sh` / `build.bat`.

Примечание для Linux: если системный `apksigner` не читает `debug.keystore`
(HmacPBESHA256 в старых JDK), можно подписать существующим ключом так:
`openssl pkcs12 -in debug.keystore -nodes -passin pass:android -out keycert.pem`,
затем выделить «чистое» PEM-содержимое (без Bag Attributes) в `key.pem`/`cert.pem`
и собрать с переменными `APKSIGNER_KEY`/`APKSIGNER_CERT`, либо запускать сборку
под Temurin 17+ (см. tools/fetch_deps.sh и CI-пример в этом файле выше).

## Изменения 0.017 (06.11.2026) — чистые списки, DPI-обход линии VPN по умолчанию, автогонка, СТОП

**1) Дубликаты вычищаются до первой проверки.** Хранилище (downloaded.txt) дедуплицируется по
каноническому ключу конфига (схема|host|port|userinfo, vmess — по id): одно и то же сервер с
разными #именами/порядком параметров считается ОДНИМ конфигом. Дедупликация запускается и при
записи («Обновить конфиги», «Быстрый поиск», «Полная проверка») ДО любой проверки. Были и
дубликаты внутри встроенного резерва — они тоже схлопнутся при первом поиске.

**2) DPI-обход на линии до VPN-сервера — ВКЛЮЧЁН ПО УМОЛЧАНИЮ.** По мотивам igareck/
anti-dpi-for-russia (см. п.2 README 0.016): причина «свежий спискок не подключается» в РФ —
ТСПУ режет рукопожатие, а не «IP умерли». Теперь перед каждым VPN-подключением поднимается
локальный ByeDPI с вашей стратегией и линия к серверу идёт через него (SNI берётся из конфига);
если не помогло — конфиг пробуется штатно. То же и в тестах «Быстрый поиск»/«Полная проверка»:
конфиг, оживившийся с обходом, НЕ удаляется; фаза «непингуемые» не трогается, пока обход включён.
Отключить: Настройки → VPN → «DPI-обход на линии до VPN-сервера». На IP-мёртвые конфиги не действует.

**3) Белых списков больше + загрузки идут и с GitHub, и через зеркала, и через Tor.**
Источники: + WHITE-CIDR-RU-all (71 конфиг, взамен пустого WHITE-CIDR-RU-checked),
+ WHITE-SNI-RU-all, (Vless-Reality-White-Lists-Rus-Mobile уже был). Миграция для тех, кто
ставил 0.015/0.016: недостающие белые списки ДОПИШУТСЯ в ваши источники один раз автоматически.
Порядок скачивания теперь: GitHub raw → GitLab-rело → Codeberg → Bitbucket → jsDelivr → (если
поднят Tor-туннель) через Tor. GitHub остаётся первым, т.к. на WiFi и через VPN он часто
работает как ни в чём не бывало.

**4) DPI больше не подаётся как «средство для YouTube».** Смысл DPI — пробивка рукопожатий
заблокированного (VPN-линии, заблокированные SNI). Режим остаётся (стратегии, тесты), но
акцент смещён внутрь VPN-системы (п.2).

**5) Во встроенный резерв скачаны ВСЕ актуальные списки на 06.11.2026** (и работают
офлайн): BLACK_VLESS_RUS_mobile, BLACK_VLESS_RUS, BLACK_SS+All, WHITE-CIDR-RU-all (71),
WHITE-SNI-RU-all (3), Vless-Reality-White-Lists-Rus-Mobile (71), wlunlocker whitelist_all
(598), wlunlocker blacklist_vpn1 (69), ByeWhiteLists2 (1031). Плюс мосты Tor (110 vanilla +
TOP100). Всего ≈ 2200 резервных конфигов без сети. WHITE-CIDR-RU-checked (0 конфигов)
убран из резерва.

**6) Универсальная кнопка «■ СТОП — остановить всё»** (под выбором режима, красным).
Останавливает: Быстрый/Полный VPN-поиск, масс-тест мостов Tor, массовый тест DPI-стратегий,
«Обновить конфиги», тихое фоновое докачивание, обновление мостов/стратегий, тайные догрузки —
и глушит туннель. Отмена кооперативная: результаты незавершённого теста НИКУДА не применяются
(ни удалений, ни записей в «Вершину»/хранилище).

**7) «Автогонка топ-3» при подключении.** Три лучших конфига поднимаются ОДНОВРЕМЕННО на
свободных портах; первый, кто открыл канал и ответил на FOREIGN-запрос, забирает туннель —
остальные два останавливаются. Если никто не прошёл — обычный последовательный перебор
(до 8). Отключить: Настройки → VPN → «Автогонка топ-3». Полноценный «балансировщик Xray
(observatory+leastPing)» рассмотрен и отклонён в пользу гонки: требует менять топологию
туннеля (много outbounds на один hev-процесс) и не даёт мгновенного личного выигрыша против
того, что уже даёт гонка + «Вершина».

**8) Проверка поддержки протоколов.** VLESS (Reality, flow=xtls-rprx-vision, fp, alpn,
fragment-НЕ поддерживается — конфиги с fragment= не оживут ни тестом, ни подключением),
Trojan (TLS по умолчанию), Shadowsocks (SIP002 + base64, method/password), VMess (всё
семейство TLS/WS/gRPC/httpupgrade/xhttp). НЕ поддерживаются в Xray-core в принципе:
hysteria2, TUIC — они честно помечаются «протокол не поддерживается ядром» при парсинге
и не тратят попытки. ss с sip002-plugin=obfs-local живёт плохо — умрёт на тесте как и любой
мёртвый конфиг. Рекомендация: ничего не менять в списках — чёрные/белые списки igareck
в основном VLESS+Reality+Vision — основной объём, всё поддерживается.

По статье «несколько агентов на проверку»: отдельного многоагентного инструмента в этой
сессии нет — вместо этого сделана явная проверка архитектурных направлений (гонка vs
балансировщик vs приоритетный перебор; хранение проверок; удаление мёртвых), см. п.7.

## Изменения 0.016 (06.11.2026) — «одна кнопка»: зеркала источников, автоцепочка VPN → Tor → DPI, честный Tor

Проблемы обратной связи: источников «не хватает» (на самом деле их было ≈2300 строк, но приложение
НЕ СКАЧИВАЛО НИ ОДНОГО байта — GitHub заблокирован в РФ, а полное обновление обрывалось проверкой
«GitHub доступен?»), Tor ни разу не подключился (чек «1 МБ за 2 с» физически недостижим через Tor),
конфиг для подключения выбирался «только из проверенных» и пользователь оставался ни с чем.

**1) Зеркала источников (главное).** Любое скачивание raw.githubusercontent.com при отказе
(в т.ч. «GitHub недоступен» из РФ) автоматически повторяется через CDN-зеркало jsDelivr
(`cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>`). Затронуто всё: «Обновить конфиги»,
массовая проверка (запись в хранилище), мосты Tor («Обновить мосты»), стратегии ByeDPI,
тихая фоновая догрузка через туннель. Проверено curl'ом 06.11.2026: все 8 источников и
7 наборов мостов скачиваются и напрямую, и через зеркало (WHITE-CIDR-RU-checked.txt —

отставать от raw; это цена работоспособности без VPN.

**2) Tor подключается.** Гейт для Tor стал мягким: «HTTP-ответ FOREIGN 1-байтного запроса

**3) Надёжный выбор конфига.** Кандидаты на подключение больше не отсеиваются наглухо:

Честно: помогает только конфигам, заблокированным по SNI/TLS; конфиги с полностью мёртвым

- **По итогам теста:**
  - прошедшие → отметка «грузит» (`configs/data_ok.txt`, sha1 → метка, живёт 7 дней);
  - не прошедшие → latency=-1, а **скачанные конфиги удаляются из хранилища**
    (`configs/downloaded.txt`); встроенные резервные удалить нельзя — они помечаются
    latency=-1 и не пойдут на подключение первыми (вообще отключаются тумблером
    «Встроенные резервные конфиги»).
- **Подключение теперь использует только прошедших тест**: если есть хотя бы одна
  свежая отметка «грузит» (< 7 дней), кандидаты на подключение — ТОЛЬКО такие
  конфиги (по возрастанию кэшированной задержки, до 5 попыток). Стартовая допроверка
  (1 МБ ≤ 2 с, 0.010) никуда не делась — двойной контроль. Если теста ни разу не
  было — поведение как раньше.
- Кнопка «Проверка путей» (TCP/TLS-пинг за 100 потоков) осталась: она быстрая и
  годится для грубой отбраковки; «Тест загрузки» — честный ответ «сквозь конфиг
  реально качается», но на ~20 конфигов и 20–30 секунд.
- Порядок действий на устройстве: «Обновить конфиги» → «Тест загрузки» →
  «Включить» (кандидаты на подключение — только прошедшие).

## Изменения 0.011 (06.11.2026) — честный пинг, серьёзные DPI-стратегии, списки обновляются вместе с конфигами

Обратная связь: «пинг подозрительно низок, 3 мс до иностранного сайта через VPN —
нереально; возможно, 404 = успех». Разобрано и исправлено:

- **Пинг TLS-конфигов теперь идёт через полный TLS-handshake** (SNI из конфига,
  без проверки цепочки — мостовой/Reality/самоподписанные конфиги не отбраковываются):
  HTTP-заглушка/редирект РКН на 443 больше не «пингуется в 3 мс», а считается мёртвой.
  Раньше проверялся только TCP-connect, который проходит к любому открытому порту.
  Для обычных Shadowsocks без TLS остаётся TCP-пинг (перехватить его нельзя, это честный
  предел метода). Для vmess TLS-хелперы не определены (сервер в base64) — тоже TCP-пинг.
- **«3 мс до иностранного сайта» само по себе не баг**: CDN-фронтенды (Cloudflare и т.п.)
  дают пользователям РФ ответ из ближайшей (московской/питерской) точки — это физическая
  реальность сети, а не измерение. А вот «жив/мёртв» теперь определяется не открытием
  порта, а ответом TLS-стека. Контрольную правду по-прежнему даёт стартовая допроверка
  (1 МБ ≤ 2 с) из 0.010. Источник «404 = успех» в пинге отсутствует: HTTP-коды там не
  участвуют (только TCP/TLS); в HTTP-проверках 4xx/5xx уже считались ошибкой с 0.009.
- **Встроенный список DPI-стратегий перезаписан**: 105 строк, каждая прогнана через
  реальный ciadpi (нода стартует — строка годна). Состав: свежие отчёты
  (hufrea/byedpi #291/#267, ByeDPIAndroid #423, август–октябрь 2026; в т.ч. с
  `-Qr` — fake TLS ClientHello с рандомизированным random/session_id, это и есть
  «серьёзные обходы с fake TLS») + ранжированный список ByeByeDPI
  (romanvht/ByeByeDPI, `proxytest_strategies.list`, обновлён 30.10.2026) + прежние строки.
  DPI-проверка при включении обходит до 12 стратегий — первыми идут наиболее свежие.
- **Списки стратегий и мостов Tor обновляются ВМЕСТЕ с «Обновить конфиги»** (fullUpdate):
  - мосты: источник Learntous7/Collect (vanilla_tested.txt) с авторезервом на
    Koros0111/OnionHop-Bridges-Collector (проверено 06.11.2026, HTTP 200, 100/165 строк);
    формат `IP:PORT [FINGERPRINT]`, ≥ 10 валидных → atomic-замена `tor_bridges_auto.txt`;
  - стратегии: источник по умолчанию — raw-файл ByeByeDPI (список обновляется разработчиками
    приложения, последний коммит репо 30.10.2026); каждая строка проходит **строгую
    валидацию флагов ciadpi** (whitelist коротких/длинных опций; строки winws/.bat-синтаксиса
    zapret, пробравшиеся в файл, отбраковываются); ≥ 10 валидных → `dpi_strategies_auto.txt`.
  - Свежий авто-список (< 30 дней) используется вместо встроенного; при отсутствии/протухании —
    встроенный. Источник можно заменить в `Настройки → DPI-обход → «Свежие стратегии DPI»`
    (пустая строка = не скачивать). В настройках видны даты последнего автообновления
    (стратегий и мостов).
- **Тихий фон при быстром канале (< 500 мс / 1 МБ)** теперь тоже обновляет мосты через
  туннель тем же общим кодом (с тем же fallback-источником), а не только VPN-конфиги.
- UI: новая строка «Свежие стратегии DPI (обновляются вместе с «Обновить конфиги»)» + дата
  последнего обновления; подвал — 0.011.

## Изменения 0.010 (06.11.2026) — допроверка канала перед «включено»

Пользовательская обратная связь: туннель «включался», но трафик не шёл (типичное
ложное «[on]»). Добавлена обязательная **допроверка запуска во всех трёх режимах**:

- Перед поднятием туннеля движок должен скачать **1 МБ за ≤ 2000 мс** через свой
  локальный SOCKS, иначе конфигурация считается нерабочей:
  - **VPN**: текущий конфиг отбрасывается, Xray останавливается, пробуется следующий
    из кандидатов (до 5); если ни один не прошёл — честная ошибка, статус НЕ «[on]».
  - **DPI**: не прошедшая стратегия останавливается, перебирается следующая из
    встроенного списка (до 12, сохранённая — первой; при выключенном автовыборе —
    только сохранённая). Цели допроверки — **заблокированные сайты** (ссылки из
    «DPI-обход → ссылки для проверки», по умолчанию YouTube), а НЕ иностранные CDN:
    открытый CDN отвечает и с мёртвым обходом, поэтому ничего не проверял бы.
  - **Tor**: мост/цепочка, не дающая 1 МБ за 2 с, приводит к честной ошибке
    («Tor поднял цепочку, но канал мёртвый…»). Автоперебор при старте не делается:
    построение цепочки слишком долгое для перебора; исправляется обновлением мостов.
- **Источники допроверки (иностранные, встроены):** Cloudflare
  (`https://speed.cloudflare.com/__down?bytes=1048576`, США, ровно 1 МБ), OVH
  (`https://proof.ovh.net/files/1Mb.dat`, Франция, ровно 1 МБ), Cachefly
  (`https://cachefly.cachefly.net/1mb.test`, CDN, ровно 1 МБ). Редактируются в
  `Настройки → Допроверка запуска` (по одному на строку).
- **Быстрый канал (< 500 мс на 1 МБ):** в фоне молча докачивается **один текстовый
  файл** — для VPN свежая подписка с конфигами (первый доступный источник из
  `Настройки → Источники`, парсинг/тестирование/дозапись как в «Обновить конфиги»),
  для Tor — свежий список протестированных Vanilla-мостов
  (`Learntous7/Collect` на GitHub, ~100 строк `IP:PORT FINGERPRINT`), сохраняется
  в `tor_bridges_auto.txt` и используется при следующих запусках Tor (приоритет:
  мосты из настроек → свежие автоскачанные (14 дней) → встроенный резерв).
  В DPI-режиме фоновая докачка не делается (локальный desync не передаёт файл целиком
  для чужих адресов). Отключается выключателем «Тихо догружать в фоне один текстовый
  файл…» (по умолчанию выключен).
- Мониторинг канала (раз в N сек) остаётся лёгким (заголовочный запрос) — 1 МБ каждые
  15 секунд генерировал бы гигабайты трафика; тяжёлая проверка выполняется только
  при старте и при переключениях.
- Мониторинг DPI теперь целим в заблокированные сайты, а не в иностранные CDN
  (иначе «канал жив» был бы ложноположительным с мёртвым обходом).
- Runtime-переключение стратегий DPI («Проверка путей» / автоперевод) по-прежнему
  доступны; автостарт теперь сразу перебирает стратегии с допроверкой.
- UI: новая секция «Допроверка запуска (VPN/Tor/DPI)», переключатель тихой
  догрузки переписан (файл + 500 мс), сброс в подвале — «0.010», под Tor —
  дата последнего автообновления мостов.
